### 4. Naming Convention Design

**Task**: Define the spec naming convention that embeds phase numbers.

**Findings**:

Pattern: `NNN-pX-Y-short-name`
- NNN: zero-padded sequential number (auto-generated by Spec Kit tooling)
- pX-Y: phase and subphase from plan.md (e.g., p1-2, p1-5, p2-3)
- short-name: 2-4 word kebab-case descriptor

Projected first specs:

| Spec # | Branch Name | plan.md Subphase |
|--------|------------|------------------|
| 001 | 001-constitution-spec-backfill | 1.1 (special — no p prefix for the foundation spec) |
| 002 | 002-p1-2-architecture-baseline | 1.2 |
| 003 | 003-p1-3-ui-token-baseline | 1.3 |
| 004 | 004-p1-5-homepage-engine-baseline | 1.5 |

**Decision**: Use `NNN-pX-Y-short-name` for all specs except 001 (which predates the convention).
**Rationale**: Embeds traceability to plan.md. Sequential numbering preserves creation order. Clarification Q2 confirmed this approach.
**Alternatives considered**: Purely descriptive names (rejected — no traceability to plan.md). Exact plan.md names (rejected — too long, don't include sequential prefix).
