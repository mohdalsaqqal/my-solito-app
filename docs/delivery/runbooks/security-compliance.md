# Security & Compliance Runbook

Purpose: define app-owned security controls and go-live checks.

## App Controls

### Runtime Validation

All state-changing route handlers must validate request bodies with Zod or an equivalent explicit runtime parser. TypeScript types are not a security boundary.

Shared schemas live in:

```text
apps/next/app/api/_lib/validation-schemas.ts
```

### Authentication & Authorization

- Better Auth owns identity.
- App-owned role resolution owns authorization.
- Release-like environments reject legacy session fallback.
- Admin APIs must call `requireAdminDomainSession()` or a narrower guard.
- Mutating browser requests must pass same-origin/fetch-metadata checks or trusted machine bypass.

### Security Headers

`apps/next/next.config.mjs` sets:

- `Content-Security-Policy`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy`

HSTS is opt-in with:

```bash
ENABLE_HSTS=true
```

Enable HSTS only after:

- production domain is final
- HTTPS is stable
- subdomains are expected to be HTTPS-only
- rollback plan is accepted

### Secrets

- Do not commit real secrets.
- `NEXT_PUBLIC_*` values are public and must not contain secrets.
- Client env files generated by `scripts/new-client.ts` belong in secret manager or deployment env, not git.

## CI Security Gates

`.github/workflows/security.yml` runs:

- CodeQL for JavaScript/TypeScript
- Dependency Review on pull requests
- Gitleaks secret scan

Hosted CI must be enabled before production handoff.

## Go-Live Security Checklist

- [ ] `yarn verify:security-compliance` passes.
- [ ] `node scripts/verify-delivery.mjs --profile security` passes.
- [ ] CodeQL workflow enabled and green.
- [ ] Dependency Review enabled for pull requests.
- [ ] Gitleaks workflow enabled and green.
- [ ] Production secrets set in Vercel/secret manager.
- [ ] `REQUIRE_PRODUCTION_AUTH=true`.
- [ ] `AUTH_COOKIE_SECURE=true`.
- [ ] `STRICT_PROVIDER_READINESS=true`.
- [ ] `ENABLE_HSTS=true` only after HTTPS/domain readiness.
- [ ] External penetration test scheduled before first high-risk launch.

## Penetration Test Scope

Minimum scope before go-live:

- auth/session flows
- admin RBAC
- checkout/order placement
- payment webhooks
- Odoo/custom backend adapter endpoints
- CMS publish/rollback
- customer PII surfaces
- file upload/media paths
- `/api/health` exposure

Record findings, fixes, and accepted risks in the client handoff pack.
